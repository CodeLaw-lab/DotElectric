# Пан — жест роутера, а не ITool

Панорамирование никогда не вело себя как инструмент редактора: у него нет идентичности в `ToolKind`, оно не переключается через UI и активируется исключительно жестом. При этом `PanTool` существовал как `ITool` и держал собственное состояние `_isPanning`, которое расходилось с состоянием роутера (Space+Left без Alt: роутер панорамировал, `PanTool` — нет). Мы удалили `PanTool`: пан — жест `CanvasInputRouter`, применяемый через `ZoomPanManager.PanCanvas`; единственный источник истины — `EditorCanvasState`.

Решающий довод: дельта панорамирования обязана считаться в стабильной системе координат окна (фиксы S45/S51 — canvas-координаты «плывут» вместе с RenderTransform). Это знание View-слоя, а `ITool` говорит модельными координатами (`PointMicrons`). Сделать `PanTool` настоящим владельцем пана можно было только через отдельный пан-seam рядом с `ITool` — шов с единственным адаптером.

## Considered Options

- **PanTool — владелец пана** (роутер детектит жест и передаёт сессию инструменту). Отклонён: требует пан-specific seam с единственным адаптером; знание стабильной оконной системы координат пришлось бы протаскивать в слой инструментов.
- **Пан — жест роутера + ZoomPanManager** (принято): единственный источник истины, поведение байт-в-байт, мёртвый код и рассинхронизация состояний удалены.

## Consequences

- Панорамирование живёт в `CanvasInputRouter` (`IsPanGesture`/`RoutePanDown`/`ApplyPan`) и `ZoomPanManager.PanCanvas`. Новый инструмент для пана не добавляем; если появится вторая поверхность пана — пересмотреть этот ADR.
- Спецификация docs/03 рисует «PanTool / PushTool по средней кнопке» — исторический артефат этапа 1, не руководство к действию.
