# Идентичность объекта в формате .tdel

Две стороны идентичности объекта в формате .tdel зафиксированы одним решением.

**Тип объекта — строка** (XML-элемент `<Type>`: «Line», «Rectangle», «Text»), единственный владелец строк идентичности — `ObjectTypeCatalog` в документной библиотеке: дескриптор типа несёт строку имени, маппинг «запись ↔ модель» и объектные правила проверки документа. Сервис шаблона и валидатор делегируют каталогу (прецедент ADR-0002 для строк форматов листа). До этого знание было разбросано по шести ручным точкам: ветвь чтения записи, ветвь записи и четыре каскада «is Line / is Rectangle / is Text» в правилах проверки; добавление типа (круг/дуга — штатный сценарий wayfinder-карты #125) требовало синхронных правок во всех.

**Идентификатор объекта стабилен через «сохранил → загрузил»**: `<Id>` пишется при сохранении и читается при загрузке; отсутствующий или пустой идентификатор в файле даёт новый (формат существующего генератора `Guid.NewGuid().ToString()`). Копия (`Clone()`) по-прежнему получает новый идентификатор — семантика вставки. До этого маппинг выбрасывал прочитанный `<Id>` и перегенерировал идентификаторы на каждый цикл, хотя сериализация обещала их хранение.

Решающий довод против enum для типа: идентичность сериализуется в файл — строка уже является границей совместимости. Enum потребовал бы parse-слой на границе файла и создал риск для файлов из более новых версий; неизвестная строка типа при загрузке молча пропускается (зафиксированное ограничение формата), неизвестный подтип модели при записи даёт запись без типа. Прецедент `ToolKind` (enum) неприменим: идентичность инструментов живёт только в процессе. Точки редактора нового типа (рендеринг, маркеры, инструменты, панели, печать, предпросмотр) остаются отдельным чеклистом — это знание редактора, не документа.

## Considered Options

- **Enum ObjectKind + маппинг на границе файла.** Отклонён: сериализуемая идентичность — строка; маппинг добавил бы второй источник написаний; поведение неизвестного типа из файла стало бы жёстче молчаливого пропуска.
- **Полиморфные хуки на модели** (`SerializeToDto`/`Validate(sheet)` на `TemplateObjectBase`). Отклонены: два механизма расширения (хуки + реестр фабрик записи); сервис и валидация потекли бы в контракт модели, которая уже несёт восемь абстрактных членов геометрии.
- **Статический каталог дескрипторов** (принят): один механизм на чтение + запись + проверку; модель не меняется вовсе; новый тип = один дескриптор; неизвестная строка — пропуск, неизвестный подтип — без дескриптора.
- **Перегенерация Id при загрузке** (статус-кво). Отклонена: сериализация обещала хранение, маппинг его выбрасывал; будущая адресация объектов (выделение по идентификатору, связи) невозможна без стабильной идентичности.

## Consequences

- Добавление типа в библиотеке: поля в плоской структуре записи (мешок сохранён ради байт-совместимости XML) + один дескриптор в каталоге — вместо поля + двух ветвей маппинга + четырёх каскадов проверки.
- Идентификаторы переживают «сохранил → загрузил»; файл с дубликатами Id сохраняет их после загрузки, и правило V-001 честно их подсвечивает (раньше дубликаты были практически невозможны из-за перегенерации).
- `Clone()` — новая идентичность: поведение вставки зафиксировано существующими тестами и не меняется.
- Запись без `<Type>` (неизвестный подтип модели) исчезает при перечитывании — побайтно с прежним поведением; отсутствие `<Id>` в старых файлах прозрачно компенсируется новым идентификатором.
- Если идентичность типа когда-либо перестанет сериализоваться строкой — пересмотреть этот ADR и вариант с enum.
